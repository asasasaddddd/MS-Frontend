# 首检检定结果自动判定设计

## 目标

删除首检检定员页面“结果判定”区域中的“检定结果”下拉框，避免检定员重复填写可以由数量直接确定的信息。

## 判定规则

- 合格数量大于 0，且不合格数量为 0：`qualified`（合格）。
- 合格数量为 0，且不合格数量大于 0：`unqualified`（不合格）。
- 合格数量和不合格数量都大于 0：`partial`（部分合格）。
- 两项都为 0 时仍由现有“数量之和必须等于申请数量”校验拦截，不新增另一套提示。

## 页面与接口

- 页面仅保留“合格数量”和“不合格数量”。
- 合格数量允许填写 0，以支持全部不合格。
- 前端提交时继续向后端传递必填的 `verificationResult`，但值由数量自动计算。
- 不修改后端 DTO、数据库和流程分支；后端现有流程本身已依据不合格数量决定后续流转。

## 测试

- 单元测试覆盖合格、不合格、部分合格三种自动判定。
- 页面合同测试确认下拉框和 `form.verificationResult` 已移除，合格数量最小值为 0，提交值来自自动判定函数。

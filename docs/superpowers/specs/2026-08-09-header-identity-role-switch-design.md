# 顶部人员身份与角色切换设计

## 目标

将页面右上角现有的“姓名与角色混合下拉框”拆分为两个职责清晰的控件：

- 姓名只展示当前登录人员的基础身份，不可点击。
- 鼠标悬停姓名时展示人员主数据中的所属部门和所属组。
- 姓名右侧提供独立的角色切换按钮。
- 角色切换继续驱动当前页面按“工号 + 角色”重新获取业务数据，不执行浏览器整页刷新。

## 展示结构

顶部右侧顺序固定为：

```text
待办消息铃铛 | 姓名 | 当前角色按钮 | 退出
```

### 姓名

- 展示 `employeeName`；姓名缺失时回退到 `employeeId`。
- 使用普通文本身份块，不提供点击、焦点或下拉行为。
- 悬停通过 Tooltip 展示：
  - 部门：`deptName`
  - 组：`groupName`
- 部门或组缺失时显示 `-`，不拼接角色授权范围。

### 角色切换按钮

- 按钮正文展示当前角色中文名称。
- 用户只有一个角色时按钮保持可见但禁用，避免顶部结构跳动。
- 用户拥有多个角色时，点击按钮展开角色菜单。
- 菜单仅展示后端登录上下文返回的 `roles`。
- 选择角色后复用现有 `handleRoleChange`：更新会话角色、必要时切换业务入口，并触发页面按新身份重新加载。

## 数据契约

人员部门和组来自 `SYS_USER` 对应的主数据字段，与当前角色、节点授权范围和跨部门提权无关。

登录和当前用户响应补充：

```text
groupId: string
groupName: string
```

字段需要贯通：

1. 后端 `LoginUser`。
2. 后端 `LoginResultVO`。
3. `LoginServiceImpl` 登录上下文及响应组装。
4. 前端 `LoginResponse`、`LoginUser` 和本地会话持久化。

不新增单独的人员信息查询请求，避免页面加载后再次请求组织信息。

## 角色切换与刷新

- 人员姓名、部门、组在角色切换时保持不变。
- 当前角色变化后，各业务页面继续监听 `employeeId|roleCode` 身份键。
- 角色切换时先取消旧角色未完成的请求，再加载新角色的待办、汇总和详情。
- 旧请求晚返回时不得覆盖新角色页面。
- 不使用 `window.location.reload()`，避免闪屏、滚动位置丢失和重复加载静态资源。

## 跨部门角色范围

- 顶部姓名 Tooltip 只显示人员主数据中的主部门、主组，不随角色授权范围变化。
- 待办、已办、汇总和详情请求只携带登录 Token 与当前角色，不使用主部门限制候选任务。
- 后端按照当前角色的全部有效部门、组授权范围返回任务并集，显式拒绝授权仍优先。
- 跨部门任务条目保留所属部门、所属组字段，便于用户区分任务来源。
- 发起类页面不新增部门或组选择器；单据组织归属直接取所选设备台账中的 `deptId/deptName` 和 `groupId/groupName`。
- 跨部门授权只决定当前角色能否操作设备，不允许人员手工改写设备台账归属。
- 批量设备的组织归属不一致时，按现有单据归属规则拆分处理，不生成一张混合部门或混合组单据。
- 不新增“当前部门切换器”，避免将人员归属、当前角色和权限范围混为同一状态。

## 响应式布局

- 桌面端完整显示姓名和当前角色名称。
- 窄屏优先保留姓名与角色按钮；角色按钮允许缩短宽度但不与姓名重新合并。
- Tooltip 不作为移动端完成业务的必要信息，人员基础数据仍保存在会话上下文中。

## 验证范围

### 前端契约测试

- 姓名身份块不是 Select、Button 或其他可点击控件。
- 姓名外层存在 Tooltip，内容包含部门和组。
- 角色切换为姓名右侧的独立按钮及菜单。
- 单角色时角色按钮可见且禁用。
- 角色切换仍调用统一的 `handleRoleChange`。
- 登录类型和转换逻辑保留 `groupId/groupName`。
- 跨部门角色切换后，页面不得只保留主部门任务，也不得残留上一角色的任务。

### 后端单元测试

- 登录响应返回用户主数据中的 `groupId/groupName`。
- Token 保存的 `LoginUser` 同样包含组信息。
- `/api/auth/me` 能返回同一份基础信息。

### 构建验证

- 前端契约测试、类型检查和生产构建通过。
- 后端认证相关测试及编译通过。

## 非目标

- 不在顶部展示工号。
- 不展示跨部门、跨组授权范围。
- 不修改角色权限计算和待办候选规则。
- 不新增人员详情弹窗或组织信息接口。
- 不为发起业务增加部门或组选择控件。

# 周检单据选择弹窗设计

## 目标

在总待办的“周检计划”汇总入口与现有角色周检工作台之间增加一个轻量选单步骤。用户点击汇总入口后先看到当前角色可处理的周检单据，再选择一张单据进入现有详情页，只查看和处理该单据下的设备条目。

## 当前问题

总待办目前把当前角色的全部周检设备聚合为一个固定入口，例如“3 张周检单、30 台设备”。点击后会直接进入角色周检工作台；因为没有携带 `planId`，工作台会同时展示全部 30 条设备，用户无法先按周检单选择处理范围。

现有周检工作台已经具备以下能力：

- 读取当前工号、当前角色的后端权威待办；
- 通过路由查询参数 `planId` 过滤一张周检单；
- 通过 `planId` 获取该单据范围内的实时状态汇总；
- 继续使用后端返回的 `allowedActions` 控制处理按钮；
- 合并工作流任务与扫码实物待办。

因此本次不新建第二套周检详情页，也不新增后端接口。

## 用户交互

### 当前待办

1. 总待办继续显示一个固定的“周检计划”入口及汇总数量。
2. 用户点击该入口的“查看详情”。
3. 页面打开“周检待办单据”弹窗，不立即跳转路由。
4. 弹窗按 `planId` 显示当前角色可见的周检单，每张单据一行。
5. 每行显示：
   - 周检单号；
   - 当前节点摘要；
   - 待处理设备条目数量；
   - “进入详情”按钮。
6. 用户点击“进入详情”后，弹窗关闭，并跳转到当前角色原有周检工作台，同时携带 `planId`。
7. 周检工作台继续使用现有逻辑，只展示该 `planId` 下的设备条目和该单据范围的汇总。

### 我的已办

“我的已办”保持现有行为。现有已办记录已经按周检单拆分并携带 `planId`，不再增加选择弹窗。

### 空状态与身份切换

- 固定周检入口数量为 0 时仍可打开弹窗，弹窗显示“当前角色暂无周检待办单据”。
- 当前角色变化、总待办重新加载或页面卸载时，关闭弹窗并丢弃旧角色的单据快照。
- 弹窗数据始终来自当前工号和当前激活角色已经通过后端权限校验的待办，不使用主部门在前端二次缩小跨部门授权范围。

## 组件与职责

### `PeriodicPlanPickerDialog.vue`

新增纯展示组件，职责仅包括：

- 接收弹窗开关状态；
- 接收已经分组的周检单据列表；
- 渲染单据号、节点摘要、条目数量和操作按钮；
- 通过事件返回用户选择的 `planId`；
- 渲染空状态。

该组件不请求接口、不读取会话、不推导角色路由，也不执行周检业务操作。

### `periodicDisplayModel.ts`

继续作为周检展示模型的单一来源：

- 复用 `buildPeriodicPlanTodoGroups()` 按 `planId` 分组；
- 将当前位于总待办组件内的周检单显示名称和节点摘要逻辑收敛为可测试的纯函数；
- 保留工作流任务与扫码待办合并后的分组结果；
- 不推导后端权限或业务状态迁移。

### `WorkspaceTodoView.vue`

只负责交互编排：

- 维护周检单据弹窗开关；
- 从当前 `periodicTasks` 生成弹窗列表；
- 周检当前待办汇总入口打开弹窗；
- 其它业务入口和周检已办入口继续使用原有路由跳转；
- 收到选中的 `planId` 后，通过 `TodoModuleAdapter` 取得当前角色周检工作台路径，再携带 `planId` 跳转。

总待办组件不得复制角色到路径的映射表。

### 现有角色周检工作台

`PeriodicTaskWorkspace.vue` 保持现有处理职责。它继续读取 `route.query.planId`，过滤任务列表并请求计划范围汇总。本次仅为其既有过滤行为增加回归测试，不新增第二套筛选逻辑。

## 数据流

```text
后端当前角色工作流待办 + 扫码实物待办
                  ↓
         WorkspaceTodoView 合并详情
                  ↓
 buildPeriodicPlanTodoGroups(periodicTasks)
                  ↓
       PeriodicPlanPickerDialog 单据列表
                  ↓ 选择 planId
 TodoModuleAdapter 解析当前角色周检工作台
                  ↓
        /periodic/{role-page}?planId=...
                  ↓
 PeriodicTaskWorkspace 过滤并处理该单设备
```

## 错误处理

- 单据详情加载失败时，不伪造单据号或把不同单据合并为一张；弹窗只展示成功解析出 `planId` 的权威详情。
- 如果汇总设备数量大于弹窗已加载条目数量，弹窗显示“部分周检详情加载失败，请刷新后重试”，避免用户误认为数据完整。
- 当前角色没有对应周检工作台路径时，不执行跳转，并显示明确错误提示。
- 跳转前再次读取当前角色，防止角色切换后使用旧角色路径。

## 视觉约束

- 使用现有 Ant Design Vue 弹窗、表格、标签和按钮，不引入新的组件库。
- 沿用当前卡片、边框、字号和颜色体系，不改变总待办布局。
- 桌面端使用紧凑表格；窄屏时允许横向滚动，不压缩单据号或操作按钮到不可读。
- 弹窗只展示选单所需信息，不在弹窗内增加设备明细、批量处理或流程按钮。

## 测试策略

### 展示模型测试

- 三张周检单、每单十条任务被分为三组，每组 `deviceCount` 为 10；
- 同一 `planId` 的扫码补充任务不会形成重复单据；
- 周检单显示名称和节点摘要稳定；
- 缺失 `planId` 的孤立任务保持独立，不错误合并。

### 组件合同测试

- 弹窗包含周检单号、当前节点、条目数量和“进入详情”；
- 点击单据按钮只发出所选 `planId`；
- 空列表显示明确空状态；
- 组件内部不存在接口调用、角色路由表或业务操作提交。

### 总待办合同测试

- 周检当前待办汇总入口打开弹窗，不直接进入角色工作台；
- 选择单据后通过周检适配器取得角色路径，并携带唯一 `planId`；
- 首检、状态变更、抽检和产品配套入口行为不变；
- 周检已办入口仍直接按 `planId` 进入历史详情。

### 回归验证

- 全量前端合同测试；
- Vue/TypeScript 类型检查；
- Vite 生产构建；
- 浏览器验证管理员、自检检定员、外委检定员、责任工程师、外扩人员和确认员的单据隔离及跳转行为。

## 非目标

- 不新增周检计划汇总后端接口；
- 不修改周检工作流节点、扫码逻辑、标签逻辑或操作权限；
- 不改变其它业务总待办入口；
- 不将弹窗扩展为新的周检处理工作台；
- 不调整“我的已办”导航层级。
